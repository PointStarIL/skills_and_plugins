# חילוץ טענות הצדדים → מסמך Word

מטרה: לקרוא כתבי ערר וכתבי תשובה מקומיים, לחלץ ולסווג את **טענות כל צד**, ולהפיק
מסמך Word עם תמצית מובנית ונייטרלית. פועל מקומית לגמרי — אין תלות ב-legal-ai,
ב-MCP או במסד נתונים. החילוץ נעשה בכוח ההיסק שלך, מונחה במדריך הארוז.

`$ARGUMENTS` = נתיבי הקבצים לניתוח (כתבי ערר/תשובה). אם ריק — בקש מהמשתמש את הנתיבים.

## שלב 0 — קרא את מדריך החילוץ (חובה, לפני הכל)
קרא את `${CLAUDE_PLUGIN_ROOT}/skills/extract-party-claims/claims-extraction-guide.md`.
זהו מקור-האמת לאיך מארגנים ומסווגים את הטענות. **חובה** לקיים אותו — במיוחד:
ארגון תמטי לפי ראש טיעון (לא רשימה שטוחה), קול פעיל של הצד, ניטרליות מלאה,
והבחנת טענות-סף מטענות-לגופו-של-עניין.

## שלב 1 — קרא את המסמכים
לכל נתיב קלט:
- **PDF** — קרא ישירות עם הכלי `Read` (הוא מפרסר PDF).
- **DOCX** — הרץ `python ${CLAUDE_PLUGIN_ROOT}/scripts/read_docx.py <path>` וקרא את הפלט.
- **TXT / MD** — קרא ישירות עם `Read`.

זהה לכל מסמך את **תפקידו**:
- כתב ערר → טענות של ה**עוררים** (`claim`).
- כתב תשובה → תשובות של ה**משיב** (ועדה מקומית / מבקשי היתר / משיבים נוספים) (`response`).
- כתב תגובה / השלמת טיעון → תגובות לתשובות (`reply`).

## שלב 2 — חלץ וסווג טענות (לפי המתודולוגיה)
לכל צד:
1. **טענות סף** (אם קיימות): חוסר סמכות, שיהוי, התיישנות, אי-מיצוי הליכים, חוסר
   יריבות, מעשה בית דין. הצג בנפרד מהטענות המהותיות. אם אין — השמט.
2. **טענות לגופו של עניין**, מאורגנות **תמטית לפי ראש טיעון** — לא רשימה שטוחה.
   כל ראש טיעון מקבץ את כל הטענות של אותו צד באותו נושא.
3. נסח כל טענה ב**קול הפעיל של הצד** ("העוררים טוענים כי...", "הוועדה משיבה כי...").
4. **ניטרליות מלאה** — אסור להעריך איכות טענה, אסור לגלות מסקנה, אסור מילות שיפוט.
5. צרף לכל טענה **מקור** קצר (למשל "כתב ערר, ס' 12" / "כתב תשובה, עמ' 4") כשאפשר.

עגן במקור: אל תמציא טענות. אם משהו לא ברור במסמך — אל תשלים אותו מהזיכרון.

## שלב 3 — בנה את מבנה ה-JSON
כתוב קובץ `claims.json` (ב-cwd של הפרויקט) לפי הסכמה:
```json
{
  "case_ref": "ערר <מספר> — <נושא קצר>",
  "subtitle": "אופציונלי",
  "parties": [
    {
      "name": "העוררים",
      "threshold_claims": [
        {"heading": "שיהוי", "text": "העוררים טוענים כי...", "source": "כתב ערר, עמ' 4"}
      ],
      "argument_heads": [
        {
          "heading": "ראש טיעון 1 — <שם הנושא>",
          "claims": [
            {"text": "העוררים טוענים כי...", "source": "כתב ערר, ס' 12"}
          ]
        }
      ]
    },
    { "name": "הוועדה המקומית", "threshold_claims": [], "argument_heads": [ ... ] }
  ]
}
```
`threshold_claims` ו-`source` אופציונליים. סדר הצדדים לפי המתודולוגיה (בערר על
אישור: עוררים → ועדה → מבקשי היתר; בערר על דחייה: מבקשי היתר/עוררים → ועדה).

## שלב 4 — הפק את ה-Word
הרץ:
```
python ${CLAUDE_PLUGIN_ROOT}/scripts/build_claims_docx.py claims.json "תמצית טענות הצדדים.docx"
```
אם הסקריפט מתלונן שחסר `python-docx` — הרץ פעם אחת `pip install python-docx` ואז נסה שוב.

## שלב 5 — דווח
מסור למשתמש את נתיב ה-`.docx` שנוצר וסיכום קצר: כמה צדדים, כמה ראשי-טיעון וטענות-סף
לכל צד. אם דילגת על משהו (מסמך לא קריא, נתון חסר) — אמור זאת במפורש.
