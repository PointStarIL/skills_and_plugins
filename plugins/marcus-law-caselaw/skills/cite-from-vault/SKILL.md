# שליפת אסמכתאות ממסד הפסיקה

## למה הסקיל הזה קיים

מסד הפסיקה מחזיק שני סוגי חומר שנראים דומה ואינם דומה: **קביעות שנקראו מפסק הדין המקורי**, ו**רשומות מפתח שהועתקו ממקור משני ולא אומתו**. בגל אימות שנערך ב-30.8.2026 נמצא שבכ-24 אחוז מרשומות המפתח יש פגם: ציטוט שנשתלה בו מילה מקובץ נבו, ייחוס לפסק דין שאינו עוסק בנושא, תאריך שגוי, וניסוח שמייבא עובדות מפסק דין אחר.

הסקיל שולף משניהם, ומחזיר אותם **מופרדים ומסומנים**, כך שבבחירת האסמכתא אי אפשר לטעות.

## נתיבי המסד

| תחום | שורש |
| --- | --- |
| ביטוח לאומי | `C:\Users\Chaim\Cowork\ניהול תיקים - ביטוח לאומי\פסיקה ביטוח לאומי` |
| דיני עבודה | `C:\Users\Chaim\Cowork\ניהול תיקים - דיני עבודה\פסיקה דיני עבודה` |

בודקים קודם לאיזה תחום שייך התיק שעל השולחן. **אין לשלוף משני המסדים באותה שאילתה.**

## הזרימה

### שלב 1: לנסח את הטענה בלשון המסד

שמות קבצי הקביעות הם משפטים תיאוריים בעברית משפטית. לפני החיפוש יש להמיר את הטענה לשניים עד ארבעה מונחים כפי שהם מופיעים בפסיקה, לא בלשון הלקוח.

למשל: "הוועדה לא הסבירה למה הורידו לו אחוזים" הופך ל-`חובת ההנמקה`, `הנמקה`, `הפחתה`.

### שלב 2: סריקת שמות הקבצים, הזולה ביותר

```bash
ls "קביעות" | grep -i "<מונח>"
```

שם הקובץ **הוא** הקביעה, ולכן הסריקה הזו לבדה עונה על רוב השאילתות. אל תקרא פתקים בשלב הזה.

### שלב 3: סריקה לפי נושא ותגיות

```bash
grep -l "^subject: <קטגוריה>" "קביעות"/*.md
grep -l "  - <תג>" "קביעות"/*.md
```

שבע הקטגוריות ב-`subject`: סמכות והכרעה; הגבול בין השאלה הרפואית לשאלה המשפטית; הליך הוועדה וחובותיה; קביעת דרגת הנכות; ענפי הגמלה וועדות הערר; פריטי ליקוי ורשימות ליקויים; ההליך בבית הדין.

### שלב 4: שכבת המפתח, אחרונה תמיד

```bash
grep -h "<מונח>" "מפתח לא מאומת"/*.md | grep "^- "
```

הנתיב עצמו מכיל את המילים "לא מאומת". זה מכוון.

### שלב 5: לפתוח רק את מה שמצטטים

קרא את פתק הקביעה המלא רק עבור הקביעות שייכנסו למסמך. משם נלקחים הציטוט, מראה המקום ומספר הפסקה.

## פלט: מנת אסמכתאות

הסדר קבוע ובלתי משתנה, גם כשקבוצה ריקה. קבוצה ריקה נכתבת ומצוין שהיא ריקה.

```
## מנת אסמכתאות: <הטענה>

### מאושר, מותר לציטוט
1. [[<שם הקביעה>]]
   מראה מקום: <citation>, פסקה <paragraph>
   תוקף: <🟢 נבדק | ⚪ טרם נבדק | 🔴 טיפול שלילי>
   שימוש בטיעון: <משפט מהפתק>

### ממתין לאישור, דורש אישור חיים לפני שימוש
...

### לא מאומת, כיוון מחקר בלבד
⛔ K0142 | <תמצית> | תיק: <מספר מנורמל>
**אסור לצטט ואסור להעתיק מראה מקום מכאן.**
```

## שני צירי אמון, בלתי תלויים

בכל פלט יש להציג **שניים**, ולעולם לא למזג אותם:

1. **ציר המקור:** האם הטקסט נקרא מפסק הדין, או הועתק ממפתח.
2. **ציר התוקף:** `negative_treatment` ו-`citations_checked`.

**קביעה מאושרת שסומנה בטיפול שלילי מסוכנת יותר מרשומת מפתח**, מפני שהיא נראית בטוחה.

## שלושה איסורים מוחלטים

1. **אין ציטוט במרכאות שמקורו אינו קאלאוט `> [!quote]` בפתק קביעה.** רשומות מפתח יושבות ב-`[!abstract]` או בשורה, לעולם לא ב-`[!quote]`.
2. **אין לכתוב מספר תיק בגוף טיוטה** אלא אם נפתח באותו סשן פתק קביעה עם מספר תיק תואם.
3. **אין ציטוט בכתב בי-דין שמקורו בערך מפתח.** ערך מפתח מוביל לחיפוש, לא למסמך.

## כשהאסמכתא הטובה ביותר היא רשומת מפתח

אין להשתמש בה. במקום זה:

1. לפתוח שורה ב-`מפתח לא מאומת/תור אימות.md` עם מזהה הרשומה, מספר התיק, והנימוק (מאיזה תיק נדרש).
2. לומר לחיים במפורש שהטענה חסרת אסמכתא מאומתת, ולהציע לשלוף את פסק הדין דרך `legal-research` (הקונקטורים של נבו ו-LawMate), ואחר כך לתעד אותו ב-`document-caselaw`.
3. **אסור לחפש פסיקה מהזיכרון או באופן עצמאי בתוך הסקיל הזה.** שליפה נעשית רק דרך `legal-research`, ורק אם חיים אישר.
4. לנסח את הפסקה במסמך בלי אסמכתא, או להשאיר סימון גלוי להשלמה.

## כשהחיפוש חוזר ריק

לפתוח את `מפתח לא מאומת/מפה של מה שאין.md`. הוא מבחין בין "הסוגיה לא קיימת במסד" לבין "הסוגיה קיימת אבל המפתחות לא מכסים אותה", וזו הבחנה שמשנה מה אומרים לחיים.

## לפני הגשה

```bash
python "_מערכת\סקריפטים\lint_citations.py" --vault "<שורש המסד>" --draft "<הטיוטה>"
```

הבדיקה נכשלת על כל מספר תיק שאין לו פתק קביעה, ולכן היא תופסת גם ציטוט ממפתח לא מאומת וגם הזיה. **קוד יציאה 1 משמעו אין להגיש.**

## אימות

- כל מראה מקום שבפלט נלקח משדה `citation` של פתק קביעה, ולא משום מקור אחר.
- כל ציטוט נלקח מקאלאוט `[!quote]`, ולא נוסח מחדש.
- הסדר בפלט קבוע: מאושר, ממתין, לא מאומת.
- לפני הגשה הורץ ה-lint והוא עבר.
